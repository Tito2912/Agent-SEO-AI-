## Parcours et règles retenus

Depuis le bilan : choisir l’analyse → exporter le PDF pour le transmettre, ou les données CSV ; l’archive manuelle reste soumise à la formule existante. Depuis les problèmes : filtrer → exporter ce périmètre. Depuis un problème : exporter ses instructions et ses URL enregistrées. Les fichiers bruts sont une lecture technique facultative, avec retour à l’analyse et à l’écran d’origine ; aucun fichier n’est appliqué sur le site depuis cette vue.

Un paramètre de retour ne confère aucun droit. Le fichier reste contrôlé par les racines résolues existantes ; le retour au projet n’est proposé qu’après vérification du projet accessible et de l’appartenance du fichier à son dossier d’analyse. L’analyse est celle du fichier, sans substitution par un rapport récent. Le PDF alternatif n’est proposé que si ce rapport précis est disponible. Les filtres utiles sont conservés, les paramètres étrangers écartés.

Règles visuelles : identité Noyaru existante, action PDF explicite, choix de données secondaires, volet natif pour les détails, contrôles de 44 px, texte lisible, contraste renforcé et focus visible. Tous les libellés réutilisent les traductions existantes. Les CSV/PDF/ZIP et les calculs ne changent pas ; pas de nouvelle mutation, publication ou droit d’accès.

## Livraison et preuves

Le composant `_report_exports.html` est commun au bilan, à la liste des problèmes et à leur détail. Les exports sont séparés des réglages de comparaison et du formulaire de filtres. Le PDF à transmettre est le premier choix ; les deux usages CSV sont distingués sans promettre toutes les URL du site. Le ZIP reste manuel, conditionné à la formule existante, avec accès au guide dans la langue réellement disponible. Les données sources sont un volet technique facultatif.

Les liens utilisent des paramètres encodés et la date du rapport affiché. La liste conserve gravité, catégorie et recherche ; le CSV d’URL ne reçoit pas de comparaison qu’il ne prend pas en charge. Les exports d’un seul problème conservent leur périmètre existant complet, même si le tableau de ses URL est recherché ou paginé. Aucun calcul ni contenu de PDF/CSV/ZIP n’est modifié. Les liens de source Google/Bing du bilan reçoivent aussi le retour contextualisé ; ceux de Performance sont encodés et nommés « Fichier CSV », puisqu’ils ouvrent une vue.

La vue `/file` conserve la barrière de racines existante, la résolution des liens symboliques, la limite de taille et les droits du compte propriétaire ou membre. Le nouveau paramètre `next` est seulement un retour : projet accessible, fichier dans son dossier, date tirée du chemin réel, seuls les filtres utiles sont conservés. Une cible externe ou un autre projet est écarté. Le PDF alternatif exige le JSON lisible de cette même analyse ; aucun rapport plus récent n’est substitué. Sans contexte valable, la sortie reste « Retrouver mes sites ».

Le texte est échappé et n’est ni exécuté ni réinterprété comme HTML/Markdown/JSON. Un fichier JSON mal formé reste consultable comme texte ; les retours à la ligne et les valeurs restent visibles. Une région nommée et accessible au clavier limite le défilement. Le chemin absolu est replié. Les états 403, 404, 413, 503 et vide ont un rendu et une sortie ; l’erreur 413 montre la taille observée et la limite en octets, sans proposer une nouvelle analyse comme remède. La lecture est bornée même si le fichier grossit après sa mesure. Aucune exception interne n’est affichée. Toutes les réponses de cette vue sont `no-store` et `no-referrer`.

Deux tests existants suivent le rendu final : le faux contexte ASGI du test de corrections contient désormais `query_string` ; le test anglais vérifie les deux groupes visibles « Filter » et « PDF and CSV exports ». Aucun changement du moteur de langues, des catalogues ou des articles de Claude.

## Limites et suite de recette

Les documents et leurs règles de génération conservent leur langue existante ; le lot localise les choix et la consultation, pas les rapports déjà produits. Un CSV d’URL exploite les URL présentes dans la source de l’analyse : il ne prouve pas l’exhaustivité de toutes les pages affectées sur le site. Les liens des fichiers Google/Bing sont revus dans le code ; aucune connexion fournisseur réelle n’est parcourue. Les fichiers hors contexte de ces écrans conservent une sortie générique sûre. Le pays manquant du collaborateur fictif affiche l’invitation existante à compléter son compte ; ce bloc partagé reste hors lot.

Production authentifiée, stockage distant réel, lecteur d’écran humain, Safari/iOS, traitements des fichiers dans les outils du prestataire et réception effective par celui-ci restent à valider en recette autorisée. Aucun partage externe, email, paiement, changement d’accès, application de fichier, fusion ou déploiement de production effectué.
