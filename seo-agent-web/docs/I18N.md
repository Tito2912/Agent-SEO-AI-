# Noyaru en plusieurs langues

Noyaru s'écrit en français. L'anglais est une **traduction** : aucun gabarit n'est dupliqué,
aucun texte français n'est remplacé par une clé technique.

## Le principe : la clé est le texte français

```jinja
<h1>{{ tr("Comprenez votre SEO.") }}</h1>
```

- En français, `tr()` affiche le texte tel quel.
- En anglais, `tr()` cherche ce texte dans `locales/en.json` :
  `"Comprenez votre SEO.": "Understand your SEO."`
- **Texte absent du catalogue → il s'affiche en français.** Un écran pas encore traduit reste
  utilisable ; il n'affiche jamais une clé ou un blanc.

Le gabarit se lit donc toujours en français, comme avant.

## Les cas courants

| Besoin | Écriture |
| --- | --- |
| Texte simple | `{{ tr("Se connecter") }}` |
| Texte avec une valeur | `{{ tr("{n} pages analysées par mois", n=gratuit.pages) }}` |
| Texte qui contient un lien ou du gras | `{{ tr_html('Consultez le <a href="{url}">comparatif</a>.', url=lien) }}` — les valeurs sont échappées |
| Texte venu du serveur (`msg`, `err`, libellés de la grille des plans) | `{{ tr(err) }}` — traduit s'il est au catalogue, sinon affiché tel quel |
| Texte d'un e-mail ou d'un module Python | `i18n.tr_current("Bonjour,")` (voir `_mail_tr` dans `app.py`) |
| Langue de la page | `<html lang="{{ current_lang() }}">` |
| Sélecteur de langue | `{% include "_lang_switch.html" %}` (ou `{% with compact = true %}…{% endwith %}`) |

**Les nombres calculés** (« 12 sites suivis », « 20 000 pages analysées/mois ») se traduisent
sans rien changer au code Python : le catalogue les connaît sous la forme
`"{0} sites suivis": "{0} tracked sites"`. Les nombres reprennent leur place, au format anglais
(`20,000`).

## Choix de la langue

1. `?lang=en` dans l'adresse (c'est ce que fait le sélecteur), mémorisé ensuite dans le cookie
   `noyaru_lang` pendant un an ;
2. le cookie `noyaru_lang` ;
3. la langue du navigateur (`Accept-Language`) : français → français, anglais → anglais, une
   autre langue seulement (allemand, espagnol…) → anglais ;
4. sinon, le français. Un robot d'indexation n'envoie en général ni cookie ni langue : il voit
   la version française, la version de référence.

## Ajouter ou modifier un texte traduit

1. Entourer le texte de `tr()` dans le gabarit.
2. Ajouter la ligne dans `locales/en.json` (texte français exact → texte anglais).
3. Lancer `python -m pytest seo-agent-web/tests/test_i18n.py`.
   Le test échoue si un texte entouré de `tr()` n'a pas de traduction anglaise, ou si une
   traduction perd une variable `{…}`.

Modifier un texte français entouré de `tr()` change sa clé : penser à mettre à jour la ligne
correspondante de `locales/en.json` (sinon le test le signale).

## Ajouter une langue

1. Créer `locales/<code>.json` (même format que `en.json`) et, pour le formulaire,
   `locales/countries_<code>.json`.
2. Ajouter la langue à `LANGUAGES` dans `backend/i18n.py`.

## Ce qui est traduit aujourd'hui

**Lot 1**
- Site public : en-tête, pied de page, bandeau cookies, accueil, tarifs (cartes et grille
  comparative), support, statut.
- Connexion, inscription (y compris la liste des pays), mot de passe oublié, réinitialisation,
  vérification de l'adresse e-mail, et les messages d'erreur de ces écrans.
- Pages d'erreur (404, 403, 500…).
- E-mails de compte : vérification, réinitialisation du mot de passe, bienvenue.

**Lot 2 — application connectée**
- Barre latérale, menu mobile, assistant (libellés), sélecteur de langue en bas de la barre.
- Écran « Projets » (liste des sites, ajout d'un site, liaison GitHub, suivi des analyses),
  premier audit, carte « prochaine étape ».
- Écran « Abonnement ».

**Lot 3 — résultats d'un audit**
- Vue d'ensemble d'un projet (score, actions prioritaires, principales anomalies, analyse en
  cours, Core Web Vitals, blocs Google Search Console et Bing, historique du score).
- Écran « Anomalies » (filtres, tableau, changements depuis l'analyse précédente).
- Les noms des 200 types d'anomalies (`audit_dashboard.ISSUE_CATALOG`) et leurs catégories.

**Lot 4 — corriger une anomalie**
- Écran « Détail d'une anomalie » (correction recommandée, actions, vérification, URL
  concernées, seuils Core Web Vitals) et fenêtre « Préparer une correction »
  (`_correction_review.html`, `static/correction-review.js`).
- Les explications « Pourquoi agir ? », les étapes de correction et de vérification de chaque
  type d'anomalie (`backend/fix_suggestions.py`), et l'aide par plateforme (WordPress, Shopify,
  Webflow, Wix : `backend/cms_guidance.py`).

**Phrases composées par le code avec une valeur du site** (« … la marque (exemple.fr) … ») : le
catalogue les connaît avec un trou nommé, `"… la marque ({domain}) …"`. Seuls les noms
`{domain}`, `{url}`, `{src}`, `{label}` et `{candidates}` ouvrent un trou dans une phrase libre ;
la valeur insérée est elle-même traduite si elle figure au catalogue. Le test
`test_every_issue_explanation_has_an_english_translation` signale toute explication modifiée dont
la traduction manque.

Textes dans du JavaScript :
- dans un `<script>` d'un gabarit : `{{ tr("…")|tojson }}` ;
- dans un fichier `static/*.js` : `noyaruT("texte français")`. Au démarrage, Noyaru repère ces
  appels dans `static/*.js` et n'envoie à la page que leurs traductions
  (`templates/_lang_script.html`). Ajouter la ligne correspondante dans `locales/en.json` ; le
  test `test_static_scripts_receive_only_their_translations` signale un oubli. En début de
  fichier : `const noyaruT = window.noyaruT || ((text) => text);`.

## Pas encore traduit

- Les autres écrans de l'application connectée (suivi des corrections, contenu, concurrents,
  mots-clés, liens entrants, réglages…). Les écrans en cours de refonte (Activité, réglages de
  l'analyse — lot 7) et l'entrée « Exécutions » de la barre latérale attendent la fusion de
  cette refonte, pour ne pas entrer en conflit avec elle.
- Les réponses de l'assistant IA et les textes du fichier `static/chatbot.js`.
- La documentation (`/docs`), les guides SEO (`/ressources-seo`) et le blog : contenus Markdown,
  à traduire comme des articles (une version anglaise par fichier).
- Les pages juridiques (CGU, confidentialité, mentions légales) : leur traduction engage
  juridiquement et doit être relue avant publication. Elles restent en français.
- Les captures d'écran de l'accueil montrent l'interface française.
- Le référencement des pages anglaises : elles partagent l'adresse des pages françaises
  (`?lang=en`). Pour qu'elles soient indexées séparément, il faudra des adresses dédiées
  (`/en/...`) et des balises `hreflang`.
